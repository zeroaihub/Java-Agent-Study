# 第三章：Embedding —— 为什么一句话能变成向量

> Day5 · 第三章学习笔记。这是 RAG 的「地基中的地基」。理解了 Embedding，你才真正理解「语义检索」为什么可能。

---

## 一、为什么学（核心价值）

RAG 的核心动作是「找出和问题相关的资料」。传统做法是**关键词匹配**（like '%年假%'），但它有致命缺陷：

- 用户问「我一年能休几天带薪假？」，文档里写的是「员工年假为 10 天」。
- 关键词层面：「带薪假」≠「年假」，「休」≠「假」，**一个字都对不上**，关键词检索直接漏掉。

但人一眼就知道它们是一个意思。**Embedding 就是让机器也能「按意思」而不是「按字面」去匹配。** 没有 Embedding，就没有语义检索，就没有 RAG。

**真实价值**：所有语义搜索、推荐、去重、聚类、RAG 召回，底层都是 Embedding。学会它，你手里就有了「让机器理解语义」的通用钥匙。

---

## 二、是什么（概念 + 底层原理）

### 2.1 一句话定义

> Embedding = 把一段文本，通过一个神经网络模型，映射成一个**固定长度的浮点数数组（向量）**，使得「语义相近的文本，向量在空间中也靠得近」。

例如（示意，真实是几百上千维）：

```
"年假"       → [0.91, 0.12, 0.03, ...]
"带薪休假"    → [0.89, 0.15, 0.04, ...]   ← 和"年假"很近
"报销流程"    → [0.05, 0.88, 0.77, ...]   ← 离得很远
```

### 2.2 为什么一句能变成向量？（底层直觉）

关键洞察：**一个词的意思，由它常和哪些词一起出现决定**（分布式语义假说）。

- 「猫」和「狗」经常出现在类似的句子里（宠物、喂养、可爱）→ 它们向量相近。
- 「猫」和「发票」几乎不共现 → 它们向量很远。

Embedding 模型（基于 Transformer，如 BERT / OpenAI text-embedding）在海量文本上训练，学会了：**把「上下文语境相似」的文本，映射到空间里相近的位置。** 于是「意思」被编码成了「坐标」。

```
        语义空间(示意,二维投影)
   ▲
   │        猫●   ●狗
   │      ●宠物
   │
   │                    ●发票
   │                 ●报销  ●财务
   └──────────────────────────────▶
   意思相近 → 挨得近；意思无关 → 离得远
```

### 2.3 为什么相似问题距离更近？

因为训练目标就是这么设计的：模型在训练时被要求「让语义相近的文本向量点积/余弦更大」。训练完成后，个性质就固化在模型权重里。所以：

- 「我一年有几天年假」 与 「员工年假为 10 天」→ 向量方向接近 → 余弦相似度高 → 被召回。
- 「我一年有几天年假」 与 「差旅报销标准」→ 向量方向差很远 → 相似度低 → 不被召回。

### 2.4 向量到底是什么？（打消神秘感）

就是一个 `float[]`。没有任何魔法。它的每一维你看不懂含义（不是「第 1 维=颜色」这种），但**整体作为一个坐标**，编码了这段文本在语义空间的位置。RAG 只关心「两个坐标离得近不近」，不关心每一维具体代表什么。

### 2.5 怎么衡量「近不近」——余弦相似度（本章重点公式）

最常用的是**余弦相似度**，只看两个向量的「方向」是否一致：

```
              A · B            Σ(Aᵢ × Bᵢ)
cos(A,B) = ───────────  =  ────────────────────
           |A| × |B|      √Σaᵢ²  ×  √Σbᵢ²
```

- 结果范围 -1 ~ 1，**越接近 1 越相似**（方向几乎重合）。
- 为什么用余弦不用「长度」：一句话说得长或短不代表意思变了，余弦忽略长度、只看方向（意思），所以最适合语义检索。

**归一化小知识**：若把向量先归一化成单位长度（|A|=|B|=1），余弦相似度就等于点积（内积）。工程上很多向量库用「内积」加速，前提是向量已归一化。

### 2.6 Embedding 模型的关键参数

- **维度（dimension）**：如 768、1024、1536、3072。维度越高表达力越强，但存储和计算越贵。
- **同模型同维度**：一个知识库从头到尾必须用同一个模型（第二章铁律），换模型要全量重建向量。
- **归一化**：有的模型输出已归一化，有的没有，影响你选内积还是余弦。

## 三、怎么用（实战：手写余弦相似度 + 说明 Java/Python/企业写法）

本章我们写第一段真正的代码：一个纯 Java 的向量工具类，负责「余弦相似度」「归一化」「点积」。它是后面向量库和检索器的数学基石。

**为什么需要这个类？** 因为无论用内存向量库还是 pgvector，「算两个向量有多像」是绕不开的核心操作。把它独立成 `util`，全项目复用、可单元测试。（代码见下方 `VectorMath.java`，已在本项目 `day05rag/util/` 生成。）

### 3.1 企业中 Embedding 的三种来源

1. **云端 API**（OpenAI text-embedding-3、通义、智谱）：效果好、免运维、但要联网+按量付费。
2. **本地模型**（bge、m3e、通过 LM Studio / Ollama 提供 embeddings 接口）：数据不出内网、免费、但要自己部署。
3. **降级/离线实现**（本项目提供的哈希向量）：无任何依赖，纯本地可跑，用于教学演示。**注意它没有真正的语义能力**（只保证同样文本得到同样向量），生产环境绝不能用，第六/七章会说明如何切换到真 Embedding。

### 3.2 Java（Spring AI）真实写法预告

Spring AI 提供 `EmbeddingModel` 接口，一行就能拿到向量：

```java
// 第六章会真正接线，这里先看它长什么样
float[] vector = embeddingModel.embed("员工年假为10天");
```

我们项目会用一个自定义 `EmbeddingClient` 接口把它包起来，这样「云端 API / 本地模型 / 离线降级」可随意切换，上层代码不用改。

### 3.3 Python 版（对照理解，不在本项目运行）

```python
from openai import OpenAI
client = OpenAI()
resp = client.embeddings.create(model="text-embedding-3-small", input="员工年假为10天")
vector = resp.data[0].embedding   # list[float]，长度 1536
```

可以看到：不管 Java 还是 Python，Embedding 对上层就是「传文本，返回 float 数组」，非常简单。复杂度都在模型内部。

## 四、用在哪（真实项目）

1. **RAG 召回**：本训练营主线，问题和文档都 Embedding 后比相似度。
2. **语义搜索**：电商「搜衣服」能搜出「上装」；企业文档搜索不再依赖精确关键词。
3. **推荐系统**：把用户和商品都 Embedding，找「向量最近」的商品推荐。
4. **去重 / 聚类**：相似工单、重复问题自动归并（向量近似即重复）。
5. **异常检测**：正常日志向量聚成一团，异常日志向量离群。

共同点：**只要涉及「按意思比较文本」，就用 Embedding。**

## 五、避坑与最佳实践

1. **问题和文档用了不同模型/不同维度** → 向量不可比，召回全错（第二章铁律，再次强调）。
2. **换了 Embedding 模型却没重建索引** → 新老向量混在一起，检索错乱。换模型必须全量重嵌。
3. **未归一化就用内积当相似度** → 长文本因向量模长大而虚高得分。要么用余弦，要么先归一化。
4. **超长文本直接 Embedding** → 超出模型输入上限被截断，尾部信息丢失。这正是要先 Chunk 的原因（第四章）。
5. **中英混排 / 特殊符号未清洗** → 噪声进入向量，降低质量。入库前做基础清洗。
6. **误以为 Embedding 懂逻辑推理** → 它只懂「语义相近」，不懂「计算/推理」。算术、多跳推理仍靠 LLM。
7. **用哈希/词袋冒充语义向量上生产** → 没有真正语义能力，召回崩溃。教学可用，生产必须用真模型。
8. **忽视 Embedding 成本与缓存** → 大批量文档重复嵌入很贵。相同文本应缓存向量（第八章）。

**性能/成本建议**：批量 Embedding（一次传多条）比逐条调用快且省；对稳定文本做向量缓存；维度不是越高越好，按召回效果和成本权衡（很多场景 768/1024 足够）。

## 六、面试问题与参考答案

**Q1：Embedding 的本质是什么？**
A：用神经网络把文本射成固定长度向量，使语义相近的文本向量在空间中距离近。本质是「把语义编码成坐标」，从而能用数学（相似度）来比较语义。

**Q2：为什么相似文本向量距离更近？**
A：基于分布式语义假说，模型在海量文本上训练，学会把「上下文语境相似」的文本映射到相近位置，训练目标本身就要求语义相近者向量相近，该性质固化在权重中。

**Q3：余弦相似度为什么适合语义检索？和内积、L2 的关系？**
A：余弦只看方向不看长度，文本长短不影响语义判断，适合语义比较；向量归一化后，内积等于余弦，工程上常用内积加速；L2 看绝对离，对未归一化向量敏感，较少直接用于纯语义召回。

**Q4：换 Embedding 模型要注意什么？**
A：必须全量重新嵌入并重建索引，因为不同模型的向量空间不兼容，且维度可能不同；查询侧也要同步换成同一模型。

- **练习：用一句话向非技术同事解释 Embedding。**
  参考：Embedding 就是给每句话在一张「意思地图」上标一个坐标，意思相近的话坐标挨得近，机器就能靠坐标远近来判断「哪些内容和你的问题是一个意思」。

- **练习：手算两个二维向量 A=[1,0], B=[1,1] 的余弦相似度。**
  参考：cos = (1×1+0×1) / (√1 × √2) = 1/√2 ≈ 0.707。方向夹角 45°，中等相似。

## 本章小结

- Embedding = 文本→固定长度向量，语义相近则向量相近，是语义检索的地基。
- 原理：分布式语义 + Transformer 训练，把「语境相似」编码成「坐标相近」。
- 相似度最常用**余弦**：只看方向；归一化后等于内积。
- 铁律：同库同模型同维度；换模型必须全量重嵌。
- 本章产出代码：`util/VectorMath.java`（余弦/点积/归一化），全项目数学基石。
