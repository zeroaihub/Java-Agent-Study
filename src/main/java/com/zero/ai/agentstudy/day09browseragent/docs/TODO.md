## ⭐⭐ 进阶（深入理解）

- [ ] **模拟并发压测**：写一个脚本并发 8 个请求（超过 pool-size=4），观察超出的请求是被阻塞还是被拒绝，验证 Semaphore 限流生效。
- [ ] **验证会话隔离**：在一个 Context 里登录某站点，紧接着新请求（新 Context）访问同站点，确认新会话没有携带上一次的登录态。
- [ ] **制造许可泄漏再修复**：故意在 `acquire()` 的 catch 里注释掉 `permits.release()`，反复触发创建失败，观察池子如何卡死；然后恢复并理解为什么这行至关重要。
- [ ] **新增一个原子动作**：在 `BrowserActionService` 里实现 `selectOption`（下拉框选择），并在 `BrowserTools` 里封装为 `@Tool`。
- [ ] **优化 Tool 描述**：故意把某个 `@Tool` 的 description 写模糊，观察大模型是否还能正确调用；再改清晰对比效果。
- [ ] **超时行为验证**：把 `navigation-timeout-ms` 调到极小（如 100ms），访问慢页面，观察超时异常是否被 `Day09ExceptionHandler` 正确捕获并返回 503/500。
- [ ] **内容截断边界**：读取一个超长页面，验证文本被截断到配置长度，思考截断策略对大模型理解的影响。

## ⭐⭐⭐ 企业挑战（生产级能力）

- [ ] **StorageState 持久化登录**：实现登录后把 `context.storageState()` 存盘，下次创建 Context 时用 `setStorageStatePath()` 恢复，实现"一次登录，多次复用"，免去重复登录。
- [ ] **Redis 会话中心**：把登录态（StorageState）与截图元数据存入 Redis，支持多实例部署时共享会话，实现水平扩展。
- [ ] **Context 复用池**：把当前"用完即销毁"改造成"复用池 + 定期回收 + 污染检测"，在性能与隔离性之间做权衡，并给出压测数据对比。
- [ ] **动作重试与幂等**：为导航/点击/下载增加有限次数的指数退避重试，处理网络抖动，同时保证幂等（不重复下单）。
- [ ] **可观测性接入**：暴露池使用率、平均借用时长、超时拒绝次数等指标到 Prometheus，并配一个 Grafana 面板。
- [ ] **Docker 化部署**：编写 Dockerfile，预装浏览器内核，处理好 `--no-sandbox`、共享内存、字体等容器化问题，让镜像开箱即用。
- [ ] **反爬对抗（合规前提下）**：在授权测试环境中，配置 User-Agent、视口、随机延迟等，理解真实自动化面临的挑战与合规边界。
- [ ] **多步任务 Agent**：设计一个需要"登录 → 搜索 → 翻页 → 提取多页数据 → 汇总"的复杂任务，验证大模型能否用现有工具自主完成，不足则补充工具。
