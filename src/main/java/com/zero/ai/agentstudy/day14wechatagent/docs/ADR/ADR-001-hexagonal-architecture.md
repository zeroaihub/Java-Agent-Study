# ADR-001：采用六边形架构 + DDD

- **状态**：Accepted
- **日期**：2026-08-04

## 背景

企业 AI WeChat Agent 需要对接多种外部系统：企业微信 Webhook、LLM、向量库、通知渠道、数据库。
若把业务逻辑与框架、外部 SDK 耦合在一起，会导致：
- 换一个 IM 渠道或 LLM 供应商就要动核心逻辑；
- 领域逻辑无法脱离 Spring / 数据库单独测试；
- 代码腐化，难以并入 ZeroHub 平台。

## 决策

采用**六边形架构（Ports & Adapters）+ DDD 分层**：

- `domain`：领域模型 + 端口接口，**不依赖 Spring / 任何框架**；
- `application`：`@Service` 用例编排，依赖领域端口；
- `infrastructure`：出站适配器（DB、LLM、通知）实现领域端口；
- `web`：入站适配器（Controller、Webhook），调用应用服务。

依赖方向**由外向内**，核心领域是稳定内核。

## 后果

**正面**：
- 领域逻辑可用纯 JUnit 测试，无需启动 Spring；
- 更换外部实现只改适配器，核心不动；
- 天然契合 Spring Modulith 模块边界与后续平台化。

**负面**：
- 接口/适配器分层带来一定样板代码；
- 团队需理解依赖倒置，学习成本略高。

## 备选方案

- **传统三层（Controller-Service-DAO）**：简单但领域逻辑易与持久化耦合，测试需依赖 DB，被否决。
- **洋葱架构**：思想相近，但六边形的「端口/适配器」隐喻更贴合本项目「多外部系统接入」的特征。
