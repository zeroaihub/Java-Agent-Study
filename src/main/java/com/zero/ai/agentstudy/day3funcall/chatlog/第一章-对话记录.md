# 第一章 对话记录：为什么 Agent 需要 Tool

> 归档时间：Day3 学习 · 第一章
> 教学框架：五段式（为什么学 / 是什么 / 怎么用 / 用在哪 / 避坑与优化）

---

## ① 为什么学（核心价值）

- 真实场景：AI 客服编造"订单已派送"→ 幻觉导致投诉、信任崩塌。
- 根源：大模型是"闭卷考试"，无法翻书（查实时）、无法动手（调接口）。
- Tool 解决三大痛点：实时性、精确性、行动力。
- 分水岭：Tool 是 LLM 从"会聊天"到"会干活"的唯一通道。

## ② 是什么（概念与原理）

- Tool：可被 LLM 按需调用、有明确输入输出契约的外部函数；LLM 不执行，只决定是否调、传什么参。
- Agent = LLM(大脑) + Tools(手脚) + 编排逻辑(神经)。
- 核心原理：大脑与手脚分离。LLM 输出结构化调用意图，程序真正执行。
- LLM vs Agent 六维对比：能力边界 / 实时数据 / 精确计算 / 真实动作 / 决策循环 / 本质。

## ③ 怎么用（实战演练）

- Java(Spring AI)：`@Tool(description=...)` 注解方法，description 是 LLM 选工具的唯一依据。
- Python(LangChain)：`@tool` 装饰器 + docstring。
- 读开源小抄：`@tool` / `bind_tools()` / `ToolNode` 都是"注册工具给大脑"。

## ④ 用在哪（应用场景）

- AI 客服 / AI 知识库(RAG) / AI 办公助手 / AI 量化交易 Agent。
- 案例拆解：客服退款 = queryOrder → checkRefundPolicy → createRefund → LLM 汇总。

## ⑤ 避坑与优化

- 常见错误：误以为 LLM 自执行、直接算数、结果直返用户、description 含糊、返回自然语言。
- 优化：减少无谓调用、超时降级、参数校验、幂等、可观测性。
- 面试题 4 道 + 最佳实践清单。

## 学员练习回答

> 问：为什么没有 Tool 的大模型只是聊天机器人？

**学员回答**：LLM 是文本大模型，没有执行能力，只有文本预测能力。Tool 给 LLM 具体的执行能力。具体的数据需要 Tool + 后端代码 + 数据库才能拿到真实的数据，LLM 不经过 Tool 处理给出的结果是幻觉。

**点评**：✅ 核心认知准确——"LLM 只有预测能力，没有执行能力"，"Tool + 后端 + 数据库"三层协作模型也抓住了本质。可以补充一点：LLM 即使知道"应该去查数据库"，它自己也做不到，必须靠 Tool 桥接。整体回答已达企业级理解水准。
