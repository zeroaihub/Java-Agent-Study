## 本章新增代码（已编译通过 BUILD SUCCESS）

- `day3funcall/registry/ToolRegistry.java` —— 工具目录，按场景分组（assistant/office/all）
- `Day3AgentService.chatWithSystem(...)` —— 带系统提示词的对话
- `Day3Controller` 新增 GET /day3/group（分组挂载）、GET /day3/tools（查看目录）

## ① 为什么学

- 真实 Agent 有几十上百工具，引发：prompt 爆炸、选择准确率下降、权限失控、查不到、异常炸穿。
- 本章决定 Agent 能否从 demo 走向生产。

## ② 是什么

- 工具目录：按场景分组，按需挂载（不全量塞给 LLM）。
- 权限：执行前硬校验（代码层），绝不依赖 LLM 自觉（防 prompt 注入）。
- 日志可观测：traceId | 用户 | 工具名 | 入参 | 出参 | 耗时 | 成功失败 | 错误码。
- 异常处理：工具捕获转 error JSON，永不抛出中断 Agent Loop。
- 企业级治理架构图：权限过滤 → 工具目录 → LLM → 日志切面 → 执行+异常兜底。

## ③ 怎么用

- ToolRegistry 分组 + getToolsByGroup。
- 分组入口 /day3/group；系统提示 chatWithSystem。
- 权限过滤伪代码（按角色 filter 工具）。
- 日志切面 @Around @Tool 方法统一记录。

## ④ 用在哪

- 大型 AI 客服：120+ 工具按订单/售后/会员域分组；按问题分类只挂对应域 8~12 个；角色分权限。

## ⑤ 避坑与优化

- 常见错误：全量挂载、LLM 判权限、工具抛异常、无 traceId、description 重叠。
- 优化：分组动态挂载、限流熔断、结果缓存、统一超时、指标监控、灰度版本。
