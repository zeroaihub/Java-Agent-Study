# 第三章 对话记录：Tool 设计原则

> 归档时间：Day3 学习 · 第三章
> 教学框架：五段式（为什么学 / 是什么 / 怎么用 / 用在哪 / 避坑与优化）

---

## ① 为什么学（核心价值）

- 血泪教训：Tool 返回自然语言 → LLM 二次加工语义漂移 + 无法程序化判断状态。
- Tool 设计能力决定 Agent 能否规模化（3 个 → 100 个工具）。

## ② 是什么（概念与原理）

- 原则一：返回 JSON —— 机器可解析、LLM 更可控、可组合。
- 原则二：不返自然语言 —— Tool 是"数据源"不是"发言人"，LLM 负责表达。
- 原则三：单一职责 —— 一个 Tool 只做一件事（queryOrder/cancelOrder/refundOrder 拆分）。
- 原则四：六要素规范 —— name / description / 参数 / 返回 / 异常 / 幂等。
- 好 Tool vs 坏 Tool ASCII 对比图。

## ③ 怎么用（实战演练）

- Java：StockTool.queryStockPrice —— 参数校验前置、失败返 error JSON、返回固定结构。
- Python：@tool + json.dumps 对照。
- 设计思考清单 7 问。

## ④ 用在哪（应用场景）

- 企业案例：量化交易 StockTool 族（queryStockPrice/queryKline/queryFinance/placeOrder/queryPosition）。
- 结构化返回 = 可组合 = Workflow 基础（price → riskCheck → placeOrder 流水线）。

## ⑤ 避坑与优化

- 常见错误：返回自然语言、万能工具、description 写实现细节、抛异常、字段不稳定、参数无描述。
- 优化：返回精简、枚举值标准化、错误码体系、版本兼容（只加不改）、description 可迭代调优。
- 面试题 4 道 + 最佳实践清单。

## 学员练习

> 设计一个 StockTool 数据结构（name / description / 参数 / 返回 JSON / error JSON）。

**学员回答**（queryStockKLine）：设计了查 K 线工具，含 @Tool/@ToolParam、参数非空校验、error JSON、按 K 线类型返回。

**点评** —— 做对的：@Tool/@ToolParam 用法正确、description 写清何时用、参数校验前置、失败返 error JSON、返回结构化。

可优化 4 点：
1. 枚举归一化：kLineType 用中文精确匹配，LLM 可能传"日K"/"daily"导致失败 → description 明确枚举(DAY/HOUR/WEEK) + 内部归一化。
2. error 带错误码：`{"code":"INVALID_PARAM","message":"..."}`。
3. 返回数据结构化：`points:[{date,open,close,high,low}]` 而非占位字符串。
4. 股票代码校验 6 位数字。

总评：已达"会做"水准，掌握 Tool 设计四原则；差距在"枚举归一化"和"错误码体系"，第七章系统讲。
