# 第二章 对话记录：Function Calling 工作原理

> 归档时间：Day3 学习 · 第二章
> 教学框架：五段式（为什么学 / 是什么 / 怎么用 / 用在哪 / 避坑与优化）

---

## ① 为什么学（核心价值）

- 核心问题：LLM 到底怎么"说"出要调哪个工具？凭什么输出精准 JSON？
- 不懂的后果：调不通（返回普通文本）、调不准（选错工具）、调不稳（参数随机出错）、优化不了。
- 一句话：Function Calling 是 Agent 的"神经传导系统"。

## ② 是什么（概念与原理）

- 精确定义：LLM 与应用的**结构化通信协议**，LLM 输出 JSON 而非自然语言，不是执行能力。
- OpenAI 三阶段协议：
  - 阶段①：请求带 tools 数组（工具菜单），name + description + JSON Schema 参数。
  - 阶段②：LLM 返回 tool_calls（content=null, finish_reason="tool_calls"），arguments 是 JSON 字符串。
  - 阶段③：回传结果（role="tool" + tool_call_id），LLM 组织最终回答（finish_reason="stop"）。
- Spring AI 内部：把三阶段封装成自动循环（while 循环直到 stop）。
- 为什么 LLM 不执行代码：底层是矩阵乘法，没有执行单元。只是学会了输出特定格式文本。

## ③ 怎么用（实战演练）

- Java(Spring AI)：`@Tool` + `@ToolParam` + `chatClient.tools(...)`，5 行替代 80 行手写协议。
- Python(LangChain)：`@tool` + `llm.bind_tools([...])`，本质把函数签名转成 tools 数组。
- 读开源小抄：`bind_tools()` = 自动生成 OpenAI tools 格式。

## ④ 用在哪（应用场景）

- 案例：AI 量化 Agent 一次决策 = getStockPrice + getKline + getNews 三 Tool 并行。
- 为什么是 Workflow 基础：Function Calling 让 LLM 能编排多个 Tool，上一个输出是下一个输入。

## ⑤ 避坑与优化

- 常见错误：未检查 finish_reason、忘记回传结果、tool_call_id 不对、arguments 直接当对象用、结果太长。
- 优化：并行执行无依赖工具、缓存结果、超时重试、大结果摘要、流式限制。
- 面试题 4 道 + 最佳实践清单。

## 学员练习

> 请画出 Function Calling 完整调用流程（三阶段 + 关键字段）。

**学员回答**：
用户输入 → LLM 识别用户意图 → 如果意图需要用 Tool 才能实现，从 tools 里获取相关 Tool → 组装 JSON 参数调用 Tool → 调用结果回传给 LLM → LLM 组装结果并判断是否还需继续执行 Tool → 如果不需要，LLM 把结果组织成自然语言返回给用户。

**点评**：✅ 非常准确，完整覆盖了三阶段协议，而且抓住了最关键的一点——"**判断是否还需要继续执行 Tool**"，这就是 Agent 循环（Agent Loop）的核心，也是它区别于"一次性函数调用"的地方。

规范化后的流程（补上关键字段）：

```
用户输入
   │
   ▼
LLM 识别意图（请求带 tools 菜单）
   │
   ├─ 不需要 Tool ──▶ 直接自然语言回答（finish_reason=stop）
   │
   └─ 需要 Tool
        │  LLM 返回 tool_calls（content=null, finish_reason=tool_calls）
        ▼
   程序组装 JSON 参数，真正执行 Tool
        │
        ▼
   结果回传 LLM（role=tool + tool_call_id）
        │
        ▼
   LLM 判断是否还需继续调 Tool？
        ├─ 需要 ──▶ 回到"返回 tool_calls"（循环 = Agent Loop）
        └─ 不需要 ─▶ 组织成自然语言返回用户（finish_reason=stop）
```

**可补充的一个细节**：LLM 一轮可能同时返回多个 tool_calls（并行调用），全部执行完再一起回传；也可能一轮只调一个、看结果后再决定下一个（串行/多轮）。你的图已经把"多轮循环"这个最难的点表达出来了。
