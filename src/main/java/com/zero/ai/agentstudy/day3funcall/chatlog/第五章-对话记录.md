## ① 为什么学

- 单工具"没得选"，多工具才是真实 Agent 形态。核心问题：多工具时 LLM 凭什么选对？

## ② 是什么

- 三工具定位：Calculator(算)/Time(实时时间)/Weather(实时外部数据)，分别对应 LLM 三大残疾。
- 路由原理：Spring AI 把所有工具转成 tools 数组，LLM 按 description 语义匹配选择。
- 多工具并行：一句话含多意图时，LLM 一轮返回多个 tool_calls，分别执行后一起回传。

## ③ 怎么用

- CalculatorTool：op 枚举 add/subtract/multiply/divide + normalize 兼容多写法 + 除零兜底。
- TimeTool：ZoneId 参数化，非法时区兜底系统默认，返回 time/zone/weekday。
- WeatherTool：模拟外部 API，返回 city/temp/desc/humidity。
- 多工具挂载：chat(msg, weatherTool, timeTool, calculatorTool)。
- 验证四个 /day3/agent 示例，核对 [XxxTool] 被调用日志。

## ④ 用在哪

- Calculator：金融/电商精确计算；Time：相对时间处理第一步；Weather：所有实时外部数据模式。
- 案例：AI 办公助手一次编排 calculate + getCurrentTime 写周报。

## ⑤ 避坑与优化

- 常见错误：description 语义重叠、包装类为 null、枚举不归一化、时区硬编码、挂载过多工具。
- 优化：按场景分组挂载、无依赖工具并行、统一返回格式、可观测性埋点。
