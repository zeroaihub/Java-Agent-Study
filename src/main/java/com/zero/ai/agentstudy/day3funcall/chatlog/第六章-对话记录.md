## ① 为什么学

- 第五章多工具是"并行独立"；真实业务常是"串行依赖"（查天气→发邮件）。
- 从"多工具选择"升级到"多工具编排"= Workflow 雏形。

## ② 是什么

- 并行 vs 串行两种协同。
- 串行原理：LLM 多轮 Agent Loop——每轮据已有结果决定下一个工具，框架自动执行回传，直到 stop。
- Agent 编排 vs 传统 Workflow：顺序由 LLM 动态决定（非硬编码），灵活但可控性弱。

## ③ 怎么用

- EmailTool：邮箱格式校验、写操作幂等、返回结构化 JSON。
- 协同入口：chat(msg, weatherTool, emailTool) —— 不写顺序代码，LLM 自动编排。
- 验证：/day3/workflow 日志中 WeatherTool 先、EmailTool 后。
- Python 对照：LangGraph create_react_agent / StateGraph。

## ④ 用在哪

- 办公写日报 / 客服自动退款 / 运维故障告警 / 量化条件下单。
- 案例：AI 运维告警 = queryMetric → 判断阈值 → queryOnCall → sendAlert。

## ⑤ 避坑与优化

- 常见错误：写操作不幂等、依赖缺失硬发、纯 LLM 编排关键交易、正文不受控、循环无上限。
- 优化：最大轮次限制、写操作加确认、失败可恢复、审计日志、正文模板化。
