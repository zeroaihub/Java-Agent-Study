# 第一章 对话记录：为什么 Agent 必须有 Memory

> 归档时间：Day4 学习 · 第一章
> 教学框架：五段式（为什么学 / 是什么 / 怎么用 / 用在哪 / 避坑与优化）

---

## ① 为什么学（核心价值）

- LLM API 调用天然无状态，不会自动记住上一轮用户说过什么。
- 普通聊天机器人如果没有 Memory，会重复询问已经说过的信息。
- Agent 必须保存上下文，才能理解代词、延续任务、用户偏好和长期目标。
- Memory 的价值是让无状态请求表现出连续服务能力。

## ② 是什么（概念与原理）

- Memory 不是模型权重更新，而是应用层保存、检索、筛选、注入上下文的机制。
- HTTP 请求天然无状态，状态需要通过 Session、Redis、数据库等外部机制维护。
- Memory 的核心流程：用户输入 -> 查询短期/长期记忆 -> 组装 Prompt -> 调用 LLM -> 保存本轮信息。

```text
用户输入
   |
   v
根据 userId / sessionId 查询 Memory
   |
   v
组装 System + 历史消息 + 长期画像 + 当前问题
   |
   v
调用 LLM
   |
   v
保存本轮对话与可沉淀信息
```

## ③ 怎么用（实战演练）

Java 核心思路：

```java
public class SimpleChatMemory {
    private final Map<String, List<String>> memory = new ConcurrentHashMap<>();

    public void add(String sessionId, String role, String content) {
        memory.computeIfAbsent(sessionId, key -> new ArrayList<>())
                .add(role + ": " + content);
    }

    public List<String> get(String sessionId) {
        return memory.getOrDefault(sessionId, List.of());
    }
}
```

```python
memory = {}

def add(session_id, role, content):
    memory.setdefault(session_id, []).append({"role": role, "content": content})

def get(session_id):
    return memory.get(session_id, [])
```

## ④ 用在哪（应用场景）

- AI 客服：记住当前订单号、问题诉求、用户等级。
- AI 办公助手：记住用户写作风格、常用周报格式、当前项目背景。
- AI 学习助手：记住用户是 Java 工程师、目标是成为 AI Agent 架构师、偏好 Java 优先。

## ⑤ 避坑与优化（进阶提升）

常见坑：

- 误以为 LLM 自带长期记忆。
- 把所有聊天记录都塞进 Prompt。
- 不做 session 隔离，造成用户信息串线。
- 把敏感信息长期保存。

最佳实践：

- 短期对话放 Redis，并设置 TTL。
- 长期画像放 MySQL/PostgreSQL。
- 每次请求必须带 userId 和 sessionId。
- 注入 Prompt 前只筛选对当前问题有用的 Memory。
