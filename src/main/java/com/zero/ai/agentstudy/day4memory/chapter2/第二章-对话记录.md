# 第二章 对话记录：Memory 分类

> 归档时间：Day4 学习 · 第二章
> 教学框架：五段式（为什么学 / 是什么 / 怎么用 / 用在哪 / 避坑与优化）

---

## ① 为什么学（核心价值）

- 如果所有信息都叫 Memory，系统设计会很快失控。
- 企业级 Agent 必须区分：当前对话上下文、长期用户画像、任务临时状态、通用知识事实。
- Memory 分类能力决定后续 Redis、MySQL、向量库、RAG 的职责边界。

## ② 是什么（概念与原理）

Memory 四类：

```text
Memory
├── Short-term Memory   最近几轮对话，解决上下文连续性
├── Long-term Memory    用户画像、偏好、目标、技能
├── Working Memory      当前任务状态、步骤、临时变量
└── Semantic Memory     抽象知识、事实、规则、经验
```

现实生活类比：

- Short-term Memory：你刚才和同事聊的几句话。
- Long-term Memory：你知道同事叫李雷，负责后端架构。
- Working Memory：你正在排查线上故障时脑中的临时变量和步骤。
- Semantic Memory：你知道 Redis 适合缓存，MySQL 适合事务存储。

## ④ 用在哪（应用场景）

AI 学习助手：

- Short-term：本章最近几轮对话。
- Long-term：用户是 Java 工程师，目标是成为 AI Agent 架构师。
- Working：当前正在学习 Day4 第二章。
- Semantic：Memory 分类、Redis、MySQL、RAG 等通用知识。

AI 客服：

- Short-term：当前订单号、当前投诉内容。
- Long-term：用户等级、服务偏好。
- Working：当前退款流程走到哪一步。
- Semantic：平台退款规则、物流政策。

## ⑤ 避坑与优化（进阶提升）

常见坑：

- 把所有聊天流水都当长期记忆。
- 把知识库文档塞进用户画像。
- 把当前任务状态永久保存。
- 把低置信度推测直接写入长期画像。

最佳实践：

- Short-term Memory 适合 Redis + TTL。
- Long-term Memory 适合 MySQL/PostgreSQL 用户画像。
- Working Memory 随任务生命周期创建和销毁。
- Semantic Memory 适合知识库、向量库，并与 RAG 协同。
