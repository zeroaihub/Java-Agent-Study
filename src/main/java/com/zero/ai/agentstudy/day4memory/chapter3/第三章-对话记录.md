# 第三章 对话记录：Chat Memory 工作原理

> 归档时间：Day4 学习 · 第三章
> 教学框架：五段式（为什么学 / 是什么 / 怎么用 / 用在哪 / 避坑与优化）

---

## ① 为什么学（核心价值）

- Chat Memory 是最常见的 Agent 记忆能力。
- 聊天越久，历史消息越多，Prompt 越长，token 成本和延迟都会上升。
- 企业级 Agent 必须控制上下文长度，否则会出现成本失控、响应变慢、上下文超限。

## ② 是什么（概念与原理）

Chat Memory 的增长规律：

```text
第1轮: system + user1
第2轮: system + user1 + assistant1 + user2
第3轮: system + user1 + assistant1 + user2 + assistant2 + user3
   ...
```

每次请求模型都要重新读取历史上下文，所以聊天越久越贵。

常见控制策略：

```text
full-history          全量历史，理解最完整，但成本持续上涨
message-window        只保留最近 N 条，成本稳定，但旧上下文会丢失
summary-compression   旧消息摘要 + 最近 N 条，兼顾成本和上下文
```

接口设计：

- `GET /api/day4/chapter3/growth-report`：查看聊天越久越贵的增长模型。
- `GET /api/day4/chapter3/strategies`：查看三种 Memory 控制策略。
- `POST /api/day4/chapter3/full-history`：完整历史策略。
- `POST /api/day4/chapter3/message-window`：滑动窗口策略。
- `POST /api/day4/chapter3/summary-compression`：摘要压缩策略。
- `GET /api/day4/chapter3/history?sessionId=s1`：查看完整历史。
- `DELETE /api/day4/chapter3/clear?sessionId=s1`：清空会话。

测试命令：

```bash
curl 'http://localhost:8080/api/day4/chapter3/growth-report'

curl -X POST 'http://localhost:8080/api/day4/chapter3/full-history' \
  -H 'Content-Type: application/json' \
```

## ④ 用在哪（应用场景）

AI 客服：

- 最近 10 轮用于理解当前订单、退款诉求、投诉细节。
- 旧对话压缩为“用户反馈订单 A1001 延迟，诉求是退款”。

AI 办公助手：

- 当前文档修改过程保留最近对话。
- 旧编辑意图压缩为摘要，避免 Prompt 无限增长。

AI 学习助手：

- 最近几轮用于理解你当前卡在哪个知识点。
- 旧章节对话压缩成学习摘要，为长期学习路径服务。

## ⑤ 避坑与优化（进阶提升）

常见坑：

- 只按消息数裁剪，不考虑 token。
- 把完整聊天流水全部塞进 Prompt。
- 摘要压缩丢失关键事实。
- 把 assistant 的错误回答沉淀成长期事实。

最佳实践：

- 完整历史用于审计，Chat Memory 只保存模型当前需要看的内容。
- 滑动窗口适合短期对话连续性。
- 摘要压缩适合长对话。
- 重要用户信息应抽取到长期 UserProfile，而不是永远保留在聊天历史中。
