## ① 为什么学（核心价值）

- 企业项目需要依赖 Memory 抽象，而不是把存储逻辑写死在业务代码中。
- Spring AI 与 LangChain4j 的共同思想是：用 conversationId 隔离会话，用 ChatMemory 管理上下文。

## ② 是什么（概念与原理）

核心关系：

```text
userId + sessionId -> conversationId -> ChatMemory -> MemoryRepository
```

ChatMemory 负责短期上下文，UserProfile 负责长期画像。


## ④ 用在哪（应用场景）

- Spring Boot 企业 Agent：通过接口替换 Redis/JDBC 存储。
- 多用户 AI 客服：使用 conversationId 隔离会话。
- 办公助手：不同文档任务使用不同 sessionId。

## ⑤ 避坑与优化（进阶提升）

- 不要用全局 Memory。
- 多实例部署时不要使用本地内存做生产存储。
- conversationId 要包含用户和会话边界。
- 框架 Memory 不等于长期用户画像。
